## Required Startup Workflow

Before doing substantial work, run these checks in order:

1. **Check credentials** — there are **two separate credential sets** for this project. Ask the user for both upfront if they are not already set:
   - **MCP / GovConnect.ai credentials** — go into `.mcp.json` as `Authorization:Bearer <ACCESS_KEY>:<SECRET_KEY>`. These authenticate against `workshop.cfg.deloitte.com`.
   - **`ai-repo` credentials** — used only for `ai-repo login`. The base URL is typically the same as `base_url` (e.g., `workshop.cfg.deloitte.com`), but if login fails or the user specifies a different host, ask and store it as `ai_repo_base_url` in `semoss_config/config.json`.
   - Never mix the two credential sets up. If the user gives you keys, confirm which system each set is for before writing anything.
   - If `.mcp.json` has placeholder values, ask the user for the MCP credentials specifically, then write them in and tell the user to restart Claude Code so MCP servers pick up the new values.
   - `.mcp.json` is gitignored — credentials inline are fine

2. **Check project config** — read `semoss_config/config.json`
   - If `project_id` is empty, ask the user for their project ID (or offer to create a new GovConnect.ai project)
   - Persist project metadata once known (`project_id`, `module`, `base_url`, `created_on`)
   - If the user wants a non-default GovConnect.ai instance, ask which instance to use and update both `semoss_config/config.json` and the URLs in `.mcp.json`

3. **Verify MCP connectivity** — try using one of the GovConnect.ai MCP tools
   - If MCP servers are not responding, credentials may be invalid — tell the user to check their access key and secret key

4. **Check for client/ directory** — if it does not exist, offer to scaffold the React app (see Scaffolding below)
   - If it exists, check `client/node_modules/` — if missing, run `cd client && pnpm install`

5. **Orient** — list the available MCP tools so the user knows what capabilities are available

## Architecture

Data flow: **Page → Hook → Service → `api.runPixel()` → GovConnect.ai SDK → Java Reactor → Database**

### Entry Point (`main.tsx`)

```typescript
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import App from './App'
import './index.css'

const queryClient = new QueryClient({
  defaultOptions: {
    queries: { staleTime: 5 * 60 * 1000 },  // 5 minutes default
  },
})

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <App />
    </QueryClientProvider>
  </StrictMode>,
)
```

### App Component (`App.tsx`)

Layer the providers in this order:

1. **ErrorBoundary** — catches React rendering errors
2. **InsightProvider** from `@semoss/sdk-react` — bridges GovConnect.ai SDK
3. **InsightBridge** — waits for SDK readiness, shows loading/error states
4. **RouterProvider** with `createHashRouter` — hash routing for GovConnect.ai iframe

```typescript
import { InsightProvider, useInsight } from '@semoss/sdk-react'
import { RouterProvider, createHashRouter } from 'react-router-dom'
import { Suspense, lazy } from 'react'

const Home = lazy(() => import('@/pages/Home'))

const router = createHashRouter([
  { path: '/', element: <Home /> },
])

function InsightBridge() {
  const { insight } = useInsight()
  // Set global insight for api.ts once ready
  // Show loading spinner until SDK initializes
  return <RouterProvider router={router} />
}

export default function App() {
  return (
    <ErrorBoundary>
      <InsightProvider>
        <Suspense fallback={<LoadingSpinner />}>
          <InsightBridge />
        </Suspense>
      </InsightProvider>
    </ErrorBoundary>
  )
}
```

### GovConnect.ai API Service (`services/api.ts`)

The core bridge between React and GovConnect.ai. Wraps the SDK's `insight.actions.run()` with typed error handling:

```typescript
let globalInsight: SemossInsight | null = null

export function setGlobalInsight(insight: SemossInsight): void {
  globalInsight = insight
}

export async function runPixel<T>(pixel: string, params?: Record<string, unknown>): Promise<T> {
  if (!globalInsight?.isReady) throw new ApiError('GovConnect.ai SDK not ready')
  const serialized = serializeParams(params)
  const fullPixel = serialized ? `${pixel}(${serialized})` : pixel
  const response = await globalInsight.actions.run(fullPixel, 'system')
  // Unwrap pixelReturn, check for errors, return typed data
}
```

Key helpers to include: `serializeParams()`, `escapeForPixel()`, `buildFilterParams()`.

### GovConnect.ai Insight Hook (`hooks/data/useSemossInsight.ts`)

Bridges `@semoss/sdk-react` with `api.ts`:

### Service Factory Pattern (`services/createService.ts`)

When the user needs CRUD operations, create a service factory:

```typescript
export function createCrudService<T extends { id: number }>(config: {
  reactorName: string
  transform?: (raw: Record<string, unknown>) => T
}) {
  return {
    getAll: (params?) => runPixel<T[]>(`${config.reactorName}GetAll`, params),
    getById: (id) => runPixel<T>(`${config.reactorName}Get`, { id }),
    create: (data) => runPixel<T>(`${config.reactorName}Create`, data),
    update: (data) => runPixel<T>(`${config.reactorName}Update`, data),
    delete: (id) => runPixel<void>(`${config.reactorName}Delete`, { id }),
  }
}
```

`loadRuntimeConfig()` fetches this file once at startup, merges over baked-in defaults, and caches the result. `getRuntimeConfig()` is the synchronous accessor used everywhere else.

## GovConnect.ai Platform Concepts

### Pixel Queries

GovConnect.ai uses a query language called Pixel. Reactors are called as functions:

```
ReactorName(param1=["value1"], param2=[2], param3=[true]);
```

**Array wrapping is required** — all Pixel parameters must be wrapped in `[]`.

### Reactor Naming

Java reactors follow a naming convention: `EntityCRUDReactor` on the Java side, but when called via Pixel, the `Reactor` suffix is stripped:

| Java Class | Pixel Call |
|------------|-----------|
| `ItemsCRUDReactor` | `ItemsCRUD(...)` |
| `GetProjectsReactor` | `GetProjects(...)` |

### Date Field Conventions

| Naming Pattern | Database Type | Example |
|---------------|---------------|---------|
| `*Date`, `*Start`, `*End` | DATE | `startDate`, `endDate` |
| `*At` | TIMESTAMPTZ | `createdAt`, `updatedAt` |

## Code Conventions

### File Organization

- **Path aliases:** Always use `@/*` → `src/*` for imports
- **No barrel files** except `@/types` and `@/services` — barrel files cause circular dependencies
- **Direct imports** for components: `import { Button } from '@/components/ui/button'`
- **Collocate tests** next to source: `Button.tsx` + `Button.test.tsx`

### Naming

- **PascalCase** for components, types, interfaces
- **camelCase** for variables, functions, hooks
- **Boolean prefix:** `is`, `has`, `should` (e.g., `isLoading`, `hasError`)
- **Hook prefix:** `use` (e.g., `useItems`, `useFormModal`)

### TypeScript Rules

- **Strict mode** always enabled
- **`function` keyword** for top-level exported functions (not `const` arrow)
- **Explicit return types** on exported hooks and utility functions
- **No return type** on React components (inferred is fine)
- **Explicit Props types** — define and export `interface FooProps { ... }`
- **No nested ternaries** — use `if`/`else` or early returns
- **No `any`** — use `unknown` and narrow

### Styling

- **Use the project theme** — colors come from `docs/theme.md`, registered via `@theme` in `index.css`. Use the generated Tailwind classes (`bg-primary`, `text-accent`, `border-neutral-light`) instead of arbitrary values.
- **Tailwind CSS only** — no inline styles, no CSS modules, no styled-components
- **Use `cn()` helper** for conditional classes
- **CSS variables** for theme tokens (colors, spacing, radii)
- **No hardcoded hex colors** in JSX — use Tailwind theme classes or CSS variables

### React Patterns

- **TanStack Query** for all server state — never `useEffect` + `useState` for data fetching
- **`createHashRouter`** — required for GovConnect.ai iframe embedding. Never use `createBrowserRouter`.
- **Lazy-load pages** with `React.lazy()` + `<Suspense>`
- **Error boundaries** around route-level components
- **FormField components** for form inputs — wrap each input with label, error display, description

### Component Structure

When creating UI components, follow this order:

```typescript
// 1. Imports
import { cn } from '@/utils/cn'

// 2. Types
interface ButtonProps { ... }

// 3. Component
export function Button({ className, ...props }: ButtonProps) {
  return <button className={cn('...', className)} {...props} />
}
```

## Build & Deploy Workflow

### Build

```bash
cd client && pnpm build
```

This runs TypeScript type-checking then Vite bundling. Output goes to `../portals/`.

### Deploy to GovConnect.ai (live publish)

**Use `scripts/claude/semoss_asset_sync.py`** for deployment. The MCP tools (`put_base64_file`, `delete_file`) can handle individual files, but the sync script is strongly preferred because it handles the full workflow: cleaning stale hashed assets, bulk uploading in one process, backing up before overwrite, and publishing once at the end.

#### Full deploy (rebuild + upload everything)

```bash
cd client && pnpm build && cd ..
python scripts/claude/semoss_asset_sync.py delete portals/assets --yes
python scripts/claude/semoss_asset_sync.py bulk-upload portals
```

Delete old `portals/assets` first because Vite emits new content hashes on every build — skipping the delete leaves dead files behind.

#### Single file upload

```bash
python scripts/claude/semoss_asset_sync.py upload portals/index.html
```

#### Script commands reference

| Command | Purpose |
|---------|---------|
| `upload <file>` | Upload a single local file (backup, delete, upload, publish) |
| `bulk-upload <dir>` | Recursively upload a directory in one process, publish once |
| `delete <remote-path> [--yes]` | Delete remote file or directory contents |
| `publish` | Publish the project (use after `--no-publish` batches) |
| `sync-from-remote <folder>` | Download remote folder to local workspace |

See `scripts/README.md` for full documentation and workflow examples.

### Submit for review with `ai-repo` CLI

**`ai-repo` is not a deployment tool** — it submits the app zip into a review/approval pipeline. The app is not published to users; it enters a `Submitted` state and awaits review. Use this when the app needs to go through a formal registration or approval process.

The `app_id` comes from `semoss_config/config.json`. Store it there once and reuse.

#### Submit a version for review

```bash
cd client && pnpm build && cd ..
zip -r portals.zip portals/
ai-repo publish portals.zip --app <app_id> --notes "<release notes>"
rm portals.zip
```

#### Check review status

```bash
ai-repo status --app <app_id>
ai-repo versions --app <app_id>
```

#### Register a new app (first-time only)

```bash
ai-repo create-app --name "<App Name>" --business-unit "<Unit>" --description "<optional>"
```

Save the returned app ID to `semoss_config/config.json` as `"app_id"`.

#### Login (first time or if credentials expired)

```bash
ai-repo login --base-url <ai_repo_base_url>/Monolith --access-key <key> --secret-key <key>
```

**Note:** `ai-repo` typically connects to the same server as GovConnect.ai — use `base_url` from `semoss_config/config.json` as the default. If login fails or the user specifies a different host (e.g., `http://localhost:9090`), ask for the correct URL and store it in `semoss_config/config.json` as `ai_repo_base_url`.

#### `ai-repo` command reference

| Command | Purpose |
|---------|---------|
| `login` | Authenticate and store credentials |
| `create-app` | Register a new app in the review system, returns app ID |
| `publish <zip> --app <id>` | Submit zip as a new version for review |
| `status --app <id>` | Check review/approval status of latest version |
| `versions --app <id>` | List all submitted versions |

## MCP Configuration

Claude Code reads `.mcp.json` from the project root automatically. Credentials are stored directly in the `Authorization:Bearer` header string. `.mcp.json` is gitignored so credentials stay out of version control.

**If MCP servers fail to connect**, the most common cause is invalid or placeholder credentials in `.mcp.json`. Update them and restart Claude Code — MCP servers only read config at startup.

Three GovConnect.ai MCP servers are configured:

| Server | Purpose |
|--------|---------|
| `Semoss_Platform_Instructions` | Platform documentation and guidance |
| `Semoss_project_manager` | Project management — create, list, upload, publish |
| `Semoss_database_helper` | Database operations — create, query, schema |

## Database Rules

If a task involves a database:

1. Ask the user to create the database or provide the database ID
2. After receiving the ID, call `get_schema(database_id)` via the MCP tools
3. The returned schema is Base64-encoded — decode it before use
4. Write the decoded schema into `semoss_config/` for reference

## Adding a New Entity (Checklist)

When the user wants to add a new data entity to the app:

1. **Database** — Define the table schema (if database-backed)
2. **Types** — Add TypeScript interface in `types/`
3. **Reactor constant** — Add reactor name to `constants/api/reactors.ts`
4. **Query key** — Add to `constants/queryKeys.ts`
5. **Service** — Create via `createCrudService()` or write a custom service
6. **Hook** — Create TanStack Query hook in `hooks/data/`
7. **Page + Route** — Create page component, add route to `App.tsx` router

## Constraints

- **Prefer `scripts/claude/semoss_asset_sync.py` for live deployment** — it handles stale asset cleanup, bulk upload, backup, and publish in one workflow.
- **Use `ai-repo` only for review submission** — it does not publish the app to users; it submits a zip into an approval pipeline.
- Prefer the GovConnect.ai MCP tools for non-deployment ops (listing files, querying databases, platform instructions)
- Do not install packages outside `client/` (no global installs, no pip)
- Do not run dangerous or destructive commands
- Always start by getting familiar with the GovConnect.ai instructions and available MCP tools
- Never use npm or yarn — pnpm only
- Never use `createBrowserRouter` — always `createHashRouter` for GovConnect.ai compatibility

## Common Pitfalls

- **Stale hashed assets after rebuild** — Vite emits new content hashes each build. Always `delete portals/assets --yes` before `bulk-upload`, or dead files accumulate on the remote.
- **Using MCP tools for full deploys** — MCP tools do not include a file upload tool; use `scripts/claude/semoss_asset_sync.py` for all deploys. Do not try to replicate upload logic manually.
- **Forgetting to publish** — Uploaded files are not visible until the project is published.
- **Confusing `ai-repo` with deployment** — `ai-repo publish` submits a zip for review; it does not publish the app to GovConnect.ai users. Use the sync script for live deployment.
- **Forgetting to `rm portals.zip`** — Delete the zip after `ai-repo publish`; it's a build artifact, not source.
- **Expired `ai-repo` credentials** — If `ai-repo versions` returns an auth error, re-run `ai-repo login`. Credentials live in the OS keychain and can expire.
- **Missing `app_id` in semoss_config** — Store the `ai-repo` app ID in `semoss_config/config.json` under `app_id` so the agent doesn't have to ask for it on every submission.
- **Stale credentials** — If MCP tools stop working, check that the credentials in `.mcp.json` are still valid.
- **Two credential sets mixed up** — The MCP/GovConnect.ai credentials (for `.mcp.json`) and the `ai-repo` credentials (for `ai-repo login`) are completely separate. If the user gives you credentials, always confirm which system they belong to before writing them anywhere.
- **`ai-repo` base URL mismatch** — `ai-repo` typically uses the same `base_url` as GovConnect.ai, but occasionally points to a different host (e.g., `http://localhost:9090`). If `ai-repo login` fails, ask the user to confirm the correct URL rather than assuming.
- **Don't hunt for or install `ai_server`** — The deploy script (`semoss_asset_sync.py`) manages its own dependencies. Just run it directly; do not try to locate, install, or rewrite around `ai_server`.
- **Wrong module path** — `api_module_url` (for API calls) and `web_module_url` (for user-facing URLs) are different paths.
- **Base64 schema** — Database schemas from `get_schema()` are Base64-encoded; decode before use.
- **npm/yarn usage** — Always use pnpm. The `preinstall` script enforces this.
- **Forgetting to build** — Run `pnpm build` before uploading to GovConnect.ai. The `portals/` directory is build output, not source.
- **Wrong Vite base path** — Must be `'./'` (relative). Absolute paths break in GovConnect.ai iframes.
- **Browser history routing** — Never use `createBrowserRouter`. GovConnect.ai portal viewer requires hash routing.
- **Build-time env vars for deployment values** — Never use Vite `define` or `import.meta.env` for model IDs, project IDs, or module paths. Use `getRuntimeConfig()` so the built bundle works across environments without rebuilding.
- **Config.json key casing** — `semoss_config/config.json` uses snake_case (`project_id`); `client/public/config.json` uses camelCase (`projectId`). Don't mix them up.
- **Barrel file imports** — Only use barrel exports from `@/types` and `@/services`. Elsewhere, import directly to avoid circular dependencies.
- **Pixel array wrapping** — All Pixel parameters must be wrapped in `[]`: `param=["value"]`, not `param="value"`.
- **Data fetching with useEffect** — Use TanStack Query hooks, never `useEffect` + `useState` for API calls.
- **Hardcoded colors** — Use Tailwind classes or CSS variables, never hex values in JSX.
